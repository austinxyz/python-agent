## 私有数据管理 — UX 重构（directory-driven items）

**OpenSpec change:** `private-data` Section 7 (revision)
**提交：** `<pending>`

### 背景

5/6 完成的初版 PrivateView 用上下两段（条目段 + 笔记段）布局，不和摄入/知识库的两栏体验一致。部署后立即被否决。本次重构以**目录**为主导航维度，模板绑定默认目录，条目和笔记在树中并存。

### 数据模型变化

- `private_entries` 新加列 `directory TEXT NOT NULL DEFAULT ''`
- 幂等迁移：`DatabaseService._ensure_private_entries_directory_column()` — try/except `duplicate column name`，对照 `_ensure_title_column` 模式
- 迁移内含**回填**：旧行（迁移前创建，directory 为空）按 `template_type → default_directory` 自动填充；不覆盖用户已设置的非空 directory；幂等
- 6 个预设模板每个加 `default_directory`：tax→税务、retirement→退休账户、portfolio→投资持仓、personal→个人基本情况、real_estate→房产资产、freeform→自由格式
- 模板模块导出 `template_default_directory(template_type)` 辅助函数 + `TEMPLATE_DEFAULT_DIRECTORIES` 字典（用于迁移回填）

### 后端 API 变化

- `GET /api/private/templates` 返回的每个模板对象现含 `default_directory` 字段
- `GET /api/private/entries` 返回的每条记录含 `directory`
- `POST /api/private/entries` 接受可选 `directory`；缺失时回填模板默认目录；持久化到 SQLite + Qdrant payload
- `PUT /api/private/entries/{id}` 接受 `directory` 更新；Qdrant payload 同步刷新（保持 AI 侧过滤一致）
- `_normalize_directory()` 验证为字符串、剥头尾 `/` 和空白
- 笔记 API 不变（`directory` 字段 V1 已经支持）

### 前端 store 变化（Pinia options API）

- 新增常量 `FIXED_TEMPLATE_DIRECTORIES`（6 个）
- 新增 getter `combinedTree`：合并 entries + notes，按 directory 切分 `/` 嵌套，每个节点 `_items[]` 存放该目录下的项目（`kind: 'entry' | 'note'` 区分），6 个固定目录种入根节点保证空 DB 也展示
- `createEntry` / `updateEntry` 接受并透传 `directory` 字段
- 状态突变全部使用展开/filter/map（不可变模式）

### PrivateView.vue 完全重写

- **两栏布局**：左侧 `w-72` 固定宽侧边栏 + 右侧 flex-1 面板（对齐 IngestView/WikiView）
- **侧边栏**：`📁 目录` header；顶部双按钮"+ 新建条目"和"+ 新建笔记"；下方递归 `DirectoryTreeNode` 组件渲染 `combinedTree`
  - 树节点：📁 目录（折叠箭头 + 子项数徽章）/ 📋 条目 / 📝 笔记
  - 选中状态用 `border-l-2 border-l-indigo-500` + 渐变背景高亮
  - `data-directory-name` 在目录名 span 上、`data-item` 在项目行上、`data-new-entry-btn` / `data-new-note-btn` 在按钮上（便于测试）
- **右侧状态机**（`rightState` ref）：`welcome` / `item-view` / `item-edit` / `new-entry` / `new-note`
  - **welcome**：渐变图标 + 操作提示
  - **item-view**：渐变 header（条目类型 / 目录 / 更新时间），内容区按 kind 分支：条目按模板字段 label/value 渲染、笔记 markdown 用 `whitespace-pre-line`；右上角"编辑""删除"

## Dirty-check 全路径覆盖（堵住静默丢草稿的最后一条缝）

**OpenSpec change:** 无（小范围修补）

### 背景

之前只在 `selectItem`（点已有条目）补了 dirty-check，**点 + 新建条目 / + 新建笔记按钮**还是会静默清空当前正在编辑的草稿。E2E `private-coverage.spec.ts` 的两个新测试在修复前必然失败（RED）。

### 实施

- `PrivateView.vue` 抽出 `confirmDiscardIfDirty()` 公共函数，根据当前 `rightState` + 对应 form 的 dirty 标志决定是否弹 `window.confirm`
- `openNewEntry` 和 `openNewNote` 都在最前调用一次 `confirmDiscardIfDirty()`；返回 false 时直接 return 保留草稿
- 弹窗文案与 `selectItem` 路径一致（「放弃当前正在编辑的新条目？」/「…新笔记？」），E2E 用 `expect(dialog.message()).toContain('放弃')` 断言

### E2E 增加 2 个测试

- 开新建条目 → 选 tax → 填标题 → 点「+ 新建笔记」→ 弹窗 → dismiss → 仍在 new-entry 面板、草稿标题保留
- 开新建笔记 → 填标题 + 内容 → 点「+ 新建条目」→ 弹窗 → accept → 切到 new-entry、之前 new-note 面板消失

### 测试统计

- E2E: **13 passed**（新增 2 个跨表单切换的 dirty-check）in ~14s
- 0 个 `__e2e_*` 孤儿

### 背景

私有数据 + 知识库 + Notion UI 重构都落地了；这一轮把核心价值——基于 RAG 的智能对话——接通。原 spec 设计走 LangGraph `create_react_agent`，实施过程中评估后**主动偏离设计**（详见下方"设计偏离"），改用确定性 RAG 链路；UX 行为对用户完全相同。

### 后端

#### 数据模型
- `chat_sessions` 加 `model TEXT NOT NULL DEFAULT 'haiku'` 列；`_ensure_chat_tables()` 幂等迁移（PRAGMA 检测 + ALTER TABLE 添加，匹配 `_ensure_title_column` 模式）
- `chat_messages` 已有的 schema 不动（id / session_id / role / content / sources / created_at 字段已就位）

#### QA agent 工具函数（`backend/app/graphs/qa_agent.py` 新建）
- `search_knowledge(query, domain=None, *, embedding, qdrant, limit=5)`：embed → `QdrantService.search_knowledge()` → 格式化为 `{content, domain, source_file_id, score, title}` 字典列表
- `search_private(query, *, embedding, qdrant, user_id="default", limit=5)`：必带 user_id 过滤
- `get_entry(file_id, *, user_id="default")`：从 `UPLOADS_PATH/<user_id>/<file_id>/<file_id>.txt` 读取；带 `Path.is_relative_to` 路径遍历守卫；缺失时返回错误 marker（不抛异常）

#### 流式编排（同文件）
- `_build_context_block(chunks)` / `_build_messages(query, chunks, history)`：把检索到的 chunk 渲染为系统级上下文块，组装最终 messages 数组
- `run_agent(queue, query, scope, *, model='haiku', history=None, search_knowledge=, search_private=, llm=)`：按 scope 预检索 → 去重 sources（按 `source_file_id`）→ 调用 `LlmService.stream_complete()` → 逐 token 推送到 queue → 完成时推 done event 含 sources → 异常推 error event → 终结哨兵 `None`
- `stream_response(queue)`：Flask SSE 生成器，从 queue 读事件并 yield `data: {...}\n\n` 直到 None

#### LlmService 扩展
- 新增 `stream_complete(messages, *, system, model, max_tokens=4096)`，**Anthropic 路径**走 `client.messages.stream(...)` 配合 `text_stream`，**OpenAI 路径**走 `chat.completions.create(stream=True)`，逐 token yield 字符串
- `_resolve_model(alias_or_id)` + `MODEL_ALIASES`：把 chat 路由传来的 `"haiku"` / `"sonnet"` 翻译为各 provider 实际模型 ID
- 所有 LLM API key/模型 仍由环境变量驱动，未硬编码

#### 路由（`backend/app/routes/chat.py` 全实现）
- `POST /api/chat`：校验 query/scope → 同步创建 session 行 + 持久化 user 消息 → 起 daemon 线程跑 `run_agent` → 返回 SSE `Response(stream_with_context(_generate()))`
- `_generate()`：tee 事件到 `assistant_chunks` 和 `final_sources`，**`try/finally` 保证客户端中途断连也写入 assistant 消息**（避免会话历史孤儿 user 消息）；持久化失败用 `logger.exception` 记录而非静默吞
- `GET /api/chat/sessions`：返回所有会话，按 created_at DESC
- `GET /api/chat/sessions/{id}`：返回会话元数据 + 全部消息（sources JSON 反序列化为列表）
- 从 `test_app_factory.py STUB_ROUTES` 移除 `/api/chat`

### 设计偏离

原 spec（design.md §2）要求 `create_react_agent` from LangGraph。实施过程中评估，**V1 的单轮 Q&A 不需要 ReAct 的多步决策**——scope 由用户在 UI 显式选择，工具确定。LangGraph ReAct 集成会引入：
- `BaseChatModel` mock 的复杂性
- `astream_events` v2 输出格式解析
- tool-call 事件的转译

而功能上和"预检索 → 上下文 → 流式 LLM"产出一样。所以走简版，design.md §2 加了 **Revision 2026-05-08** 说明。3 个工具函数保留为可独立测试的 Python，将来升级 ReAct 时直接接入。

### 代码审查发现

| 级别 | 问题 | 修复 |
|------|------|------|
| HIGH | 客户端中途断连，`_generate` 的 persist 块跑不到，会话留 user 消息但无 assistant 回复 | 把 persist 放到 `try/finally` 的 finally 块，断连也保存到那一刻为止已收到的 token |
| HIGH | persist 失败用 `except Exception: pass` 静默吞，违反项目"never silently swallow errors"约定 | 改成 `logger.exception(...)`，post-mortem 时能定位 |
| HIGH | `_ensure_chat_tables` 用裸 `sqlite3.connect` 而不是 `with` context manager | 不修复——和 `_ensure_title_column` / `_ensure_private_*` 三个现有迁移完全同一个模式；改这一个会和其他三个不一致。如果将来集体重构再统一 |
